# Shipped with known gap — PR #10232

PR #10232 merged with 37 unresolved adversarial concern(s) that survived all gates without an explicit ConcernResolution. Future planners / reviewers should treat these as known gaps until either addressed in a follow-up PR or explicitly accepted.

## Unresolved concerns

- **HIGH** `PLAN-ASSUMP-001` (raised in `plan` / `assumption_surfacer`): UI test strategy is unspecified. The acceptance criteria require 'A UI unit test asserts the fork arms use alignItems: flex-start', but the mechanism (getComputedStyle inspection, snapshot test, visual regression tool) is unclear. The test approach could be fragile or fail to catch the regression if misdesigned.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-002` (raised in `plan` / `assumption_surfacer`): Header.jsx alignment is assumed but not verified. The issue says 'if it shows the same misalignment' but the planner has no plan for how/when this verification happens. If Header.jsx uses different styling or a different markup structure, the fix might be more complex. Verification should precede the plan.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-003` (raised in `plan` / `assumption_surfacer`): Glyph bearing normalization is marked 'optional' but is acknowledged as a 'secondary contributor' to the misalignment. The flex fix alone may not visually solve the problem if the glyphs have significantly different bearings. Decision to normalize (or measure and confirm negligibility) should be upfront, not deferred to implementation.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-004` (raised in `plan` / `assumption_surfacer`): Scope of TerminalFork callers is incompletely scoped. The grep found StreamView and Header, but the issue doesn't confirm this is exhaustive. Other components (outside src/ui/src) or future callers might inherit the same misalignment pattern.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-005` (raised in `plan` / `assumption_surfacer`): Responsive/mobile viewport behavior is not discussed. The fix assumes flex alignment is consistent across screen sizes, but no explicit verification on mobile breakpoints. If breakpoints exist in the theme or component, they should be checked.
  - _must_address_by_: `planner`
- **LOW** `PLAN-ASSUMP-006` (raised in `plan` / `assumption_surfacer`): Code duplication: StreamView.jsx and Header.jsx have nearly identical flex column + alignItems structures. After the fix, consider extracting the fork style object to a shared constant to reduce maintenance burden.
  - _must_address_by_: `implementer`
- **CRITICAL** `PLAN-BUILDER-001` (raised in `plan` / `plan_council_builder`): Scope of TerminalFork callers unconfirmed. Pending concern ASSUMP-004 flags the caller scope as 'incompletely scoped' — only StreamView and Header are named. The plan must confirm: does `grep -r TerminalFork` across the full codebase find only these two files, or are there other callers (e.g., elsewhere in src/ui, integration layers, or future consumers) that would also inherit the misalignment bug and need the same fix? If callers exist outside the plan's file list, the task boundary is ambiguous.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-BUILDER-002` (raised in `plan` / `plan_council_builder`): Test assertion mechanism assumes but does not confirm testid existence. The plan specifies 'assert the fork container's `style.alignItems === 'flex-start'` via its `data-testid`' but does not verify the testid already exists on the fork container in StreamView, Header, or TerminalFork. If the testid is missing and must be added: (a) Adding to TerminalFork violates the 'TerminalFork stays untouched' constraint. (b) Adding to the caller's markup is a small change but should be explicit in 'Files to Modify.' Need confirmation: what is the selector/testid strategy for the test assertion?
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-BUILDER-003` (raised in `plan` / `plan_council_builder`): Header.jsx verification procedure is implicit, not explicit. If Header uses different styling or markup structure than StreamView, the fix might differ. Clarify: is step 1 'Read Header.jsx and confirm the symptom' or 'Read Header.jsx and assume it has the same pattern'?
  - _must_address_by_: `planner`
- **CRITICAL** `PLAN-TESTER-001` (raised in `plan` / `plan_council_tester`): No automated test for the core behavioral fix. Plan requires a unit test asserting `alignItems === 'flex-start'`, but the mechanism is unspecified. Can the test suite access computed styles, or only inline styles? If the style is applied via CSS modules or theme tokens, `element.style.alignItems` may be empty. Without a working assertion, the test doesn't actually catch regression if alignItems reverts to 'center'.
  - _must_address_by_: `planner`
- **CRITICAL** `PLAN-TESTER-002` (raised in `plan` / `plan_council_tester`): Visual alignment regression not testable.
