# Shipped with known gap — PR #10422

PR #10422 merged with 17 unresolved adversarial concern(s) that survived all gates without an explicit ConcernResolution. Future planners / reviewers should treat these as known gaps until either addressed in a follow-up PR or explicitly accepted.

## Unresolved concerns

- **HIGH** `PLAN-ASSUMP-001` (raised in `plan` / `assumption_surfacer`): Assumption that these are independent duplicates is unverified. The erosion loop detected cross-module appearance but has not shown proof they're duplicated (not shared imports from a common location). Must inspect actual file contents to confirm each module independently defines _GIT_TIMEOUT_S rather than importing it.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-002` (raised in `plan` / `assumption_surfacer`): Assumption about semantic compatibility is unverified. Even with identical symbol names, the definitions may differ in value (e.g., different timeout values for different subsystems) or purpose. Consolidating incompatible definitions risks breaking code. Must inspect actual definitions before deciding on unification.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-003` (raised in `plan` / `assumption_surfacer`): Tool mechanism assumption: erosion metrics loop correctly identifies symbol locations across 3 modules and files. Validate in a scratch repo or by reading the actual files to confirm detection accuracy before committing to this mechanism in the plan.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-004` (raised in `plan` / `assumption_surfacer`): Heuristic is explicitly marked PROVISIONAL v1. This signals the signal itself may evolve in future iterations, affecting confidence in durability of this finding. Should influence whether to treat as urgent vs. deferred.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-005` (raised in `plan` / `assumption_surfacer`): Consolidation approach is underspecified. The issue frames this as 'whether these should be unified' but doesn't clarify: where should the unified version live (shared config module? new utils module?), what are the architectural decision criteria (coupling cost vs. duplication cost), or how does this interact with module layering?
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-001` (raised in `plan` / `assumption_surfacer`): Consolidating `_GIT_TIMEOUT_S` to a shared location may create circular import dependencies if the shared module is placed mid-hierarchy and imported upward. Needs architectural review of current import edges before choosing consolidation location.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-002` (raised in `plan` / `assumption_surfacer`): Architectural placement mechanism: assumption that a suitable shared location exists without violating module-layering rules (per architecture-layers.md and ADR-0021). Planner must validate the chosen location does not introduce coupling violations or import-cycle risks before committing to consolidation.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-003` (raised in `plan` / `assumption_surfacer`): Different modules' git operation contexts may require different timeout strategies (e.g., audit scanning vs. escape detection have different latency profiles). Identical timeout value could be suboptimal or incorrect for some modules despite sharing the symbol name.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-004` (raised in `plan` / `assumption_surfacer`): Single-symbol fix may mask a broader pattern. No evidence that this is an anomaly vs. a systemic issue indicating inadequate refactoring discipline. Scope unclear: should this trigger a holistic audit for similar duplication across the codebase?
  - _must_address_by_: `planner`
- **CRITICAL** `SPEC-JUDGE-001` (raised in `plan` / `spec_judge`): AC#1 grep pattern contradicts the stated refactoring approach. The AC specifies 'grep -rn "_GIT_TIMEOUT_S\b" src/' will find 8 matches (1 definition + 7 imports), but the plan explicitly renames the constant from `_GIT_TIMEOUT_S` (private, underscore-prefixed) to `GIT_READONLY_TIMEOUT_S` (public, no underscore). After migration, a grep for `_GIT_TIMEOUT_S\b` should return ZERO results, not 8. The AC is testing for the old name that should no longer exist. Either the AC pattern must be `GIT_READONLY_TIMEOUT_S` or the AC is unverifiable as written.
  - _must_address_by_: `implement`
- **CRITICAL** `SPEC-JUDGE-002` (raised in `plan` / `spec_judge`): AC#7 regression test scan will trivially pass due to pattern mismatch. The regex `_GIT_TIMEOUT_S\s*=\s*60` will find zero results after migration (the constant is renamed to `GIT_READONLY_TIMEOUT_S = 60` in git_timeouts.py). The test appears to verify deduplication, but will report success even if refactoring was skipped. The AC needs to grep for the new name `GIT_READONLY_TIMEOUT_S = 60` to actually verify the migration succeeded.
  - _must_address_by_: `implement`
- **HIGH** `SPEC-JUDGE-003` (raised in `plan` / `spec_judge`): No AC validates the PLAN-ASSUMP-001 finding that the 7 modules independently define identical `_GIT_TIMEOUT_S = 60` values rather than importing from a common location. The plan asserts this as a prerequisite but provides no testable verification in the ACs. If any module already imports from a shared source (contrary to assumption), the refactoring creates redundant indirection. An AC should verify each module currently has a local definition, not an import.
  - _must_address_by_: `implement`
- **HIGH** `SPEC-JUDGE-004` (raised in `plan` / `spec_judge`): No AC validates architectural safety for the chosen placement (src/git_timeouts.py as a leaf). PLAN-ASSUMP-001 and PLAN-ASSUMP-002 flag circular import and module-layering risks. The plan claims git_timeouts.py is 'zero-dependency' (tested by AC#3), but doesn't verify that importing it from 7 scattered modules doesn't create upward-directed edges that violate architecture-layers.md. An AC should verify that each importing module's layer >= git_timeouts.py's layer.
  - _must_address_by_: `implement`
- **HIGH** `SPEC-JUDGE-005` (raised in `plan` / `spec_judge`): AC#4 assumes existing unit tests for the 7 adapted modules verify timeout behavior, but doesn't confirm this. If the existing tests only check functional correctness (e.g., 'git log returns expected commits') without checking timeout enforcement (e.g., 'timeout parameter passed to subprocess is 60'), then test passage alone does not prove behavior preservation. An AC should either list the specific existing tests that exercise the timeout value or add explicit timeout-verification assertions.
  - _must_address_by_: `implement`
- **MEDIUM** `SPEC-JUDGE-006` (raised in `plan` / `spec_judge`): AC#1 ambiguity on 'import sites'. The AC says 'exactly 8 matches: 1 definition line...and 7 import sites' but doesn't clarify whether 'import sites' means: (a) import statements (`from git_timeouts import GIT_READONLY_TIMEOUT_S`), (b) usage sites (`timeout=GIT_READONLY_TIMEOUT_S`), or (c) both. Depending on the grep pattern, these counts differ. The AC must be concrete about what constitutes a 'match' for the grep scan to be reproducible.
  - _must_address_by_: `implement`
- **MEDIUM** `SPEC-JUDGE-007` (raised in `plan` / `spec_judge`): Plan's rationale that 60s timeout is semantically correct for all 7 modules is asserted but not verified by any AC. PLAN-ASSUMP-003 notes 'Different modules' git operation contexts may require different timeout strategies'. While the plan justifies this as 'local, read-only git log/diff/rev-parse, failure-tolerant', an AC should verify that all 7 modules are actually used in only these contexts (not, e.g., in a performance-critical fast-path where 60s is too long). Current ACs cannot detect this mismatch.
  - _must_address_by_: `implement`
- **MEDIUM** `SPEC-JUDGE-008` (raised in `plan` / `spec_judge`): Pending concern PLAN-ASSUMP-004 identifies potential systemic duplication (broader than these 7 modules). Plan scope explicitly excludes this ('Single-symbol fix may mask a broader pattern'), but no AC verifies scope boundaries. An AC should confirm that only these 7 named modules currently redefine the 60s tier, or acknowledge that the fix is incomplete. A runtime glob scan (AC#7) could detect additional scattered definitions if the regex pattern were corrected.
  - _must_address_by_: `implement`
