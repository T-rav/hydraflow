# Shipped with known gap — PR #10521

PR #10521 merged with 30 unresolved adversarial concern(s) that survived all gates without an explicit ConcernResolution. Future planners / reviewers should treat these as known gaps until either addressed in a follow-up PR or explicitly accepted.

## Unresolved concerns

- **CRITICAL** `PLAN-ASSUMP-001` (raised in `plan` / `assumption_surfacer`): Attribution confidence is explicitly 'low' — the link between this bug and PR 10440 may be incorrect. If the wrong PR is identified, root-cause analysis targets the wrong code.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-002` (raised in `plan` / `assumption_surfacer`): Mechanism: originating_merge_sha is missing. Validate that PR 10440 was actually merged (not drafted/stalled) and obtain its merge SHA before accepting the attribution.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-ASSUMP-003` (raised in `plan` / `assumption_surfacer`): Mechanism: 'fixes-chain' attribution method is opaque. Unclear how the EscapeLedgerLoop determines which PR introduced a bug — if it's heuristic-based (commit messages, file matching, etc.), validation against actual code changes in PR 10440 is load-bearing.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-004` (raised in `plan` / `assumption_surfacer`): No encoding strategy yet (encoded_as: none-yet). Planner must decide whether this bug warrants a regression test, detector, stored lesson, or ADR to prevent recurrence.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-ASSUMP-005` (raised in `plan` / `assumption_surfacer`): time_to_detection_hours is missing — unknown how long the bug existed before detection. This affects severity assessment and encoding choice (long-lived escapes may warrant detector; rapid detection suggests code-review miss).
  - _must_address_by_: `planner`
- **CRITICAL** `PLAN-TESTER-001` (raised in `plan` / `plan_council_tester`): No automated test verifies that escape 055267e7b2b7 actually originates from PR #10440. The plan states 'Verified read-only: 055267e7b2b7 adds tests/regressions/test_issue_10440.py' but provides no automated assertion that the commit-to-PR attribution chain is correct. If the wrong PR is blamed, the regression-pin classification is still correct in mechanism but wrong in fact—the encoded lesson targets the wrong code. Test gap: detect_escapes on 055267e7b2b7 should yield originating_merge_sha matching PR #10440's actual merge commit, validated against the live repo.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-TESTER-002` (raised in `plan` / `plan_council_tester`): No automated test verifies that medium-confidence escapes are filtered from escape.metrics low-confidence output. The acceptance criteria confirm classification as 'medium', but not the integration point: that medium-confidence records are absent from the low-confidence HITL surface. The scenario test says 'That tick files no hydraflow-find issue on FakeGitHub' but doesn't assert the metric itself. Test gap: escape.metrics after processing a medium-confidence candidate should have length == 0 (not just absent from issue filing).
  - _must_address_by_: `planner`
- **HIGH** `PLAN-TESTER-003` (raised in `plan` / `plan_council_tester`): No automated test verifies that the marker sentinel itself is safe from splitlines() boundary corruption. Acceptance criterion 'No marker or delimiter in src/escape/detect.py uses a character str.splitlines() treats as a boundary' is a code-review assertion, not an automated gate. A future maintainer could introduce a marker with U+2028/U+2029 and pass all unit tests. Test gap: a unit test that validates _SHA_MARKER against str.splitlines() to confirm it's invariant under that operation.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-TESTER-004` (raised in `plan` / `plan_council_tester`): Paths with spaces, unicode, or embedded newlines are listed as edge cases ('paths with spaces/unicode (only the marker moves, no quoting change)') but no explicit test is mentioned in the test plan. The regression and scenario tests may seed only simple ASCII filenames. Test gap: test_issue_10499.py should include a commit that adds tests/regressions/file_with_spaces.py and tests/regressions/文件.py, asserting both appear in added_paths.
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-TESTER-005` (raised in `plan` / `plan_council_tester`): Empty ranges and git-absent scenarios are listed as edge cases ('empty ranges; git absent or non-repo still returns None via _run_git') but acceptance criteria and test descriptions don't explicitly confirm test coverage. P2 lists 'A range with no added files returns an empty mapping' but this is ambiguous with 'range has no commits at all'. Test gap: explicit test for commits_for_range on an empty revision range (e.g., HEAD..HEAD or on a fresh repo with no commits yet).
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-TESTER-006` (raised in `plan` / `plan_council_tester`): No test verifies that the fix does NOT retroactively reclassify already-written escape rows. The plan states 'already-written rows keep detection_source="bug-issue"' but the tests only cover forward classification of new commits. Test gap: escape ledger data from before this fix is applied should retain detection_source='bug-issue' after the fix is deployed (or explicitly document that ledger is not retroactively corrected and why).
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-TESTER-007` (raised in `plan` / `plan_council_tester`): Pending concern PLAN-ASSUMP-002 (originating_merge_sha missing) is not addressed by test strategy. The fix assumes PR #10440 was merged and has a definitive merge SHA, but no test validates that the merge actually exists in the repo state used by the scenario. Test gap: test_escape_ledger_scenario.py should seed a real merge (not just a commit) and assert that originating_merge_sha is populated for the resulting regression-pin escape.
  - _must_address_by_: `planner`
- **LOW** `PLAN-TESTER-008` (raised in `plan` / `plan_council_tester`): No test explicitly covers the multi-commit range case mentioned in acceptance criteria. 'Added paths attribute to the commit that added them, not merged across a multi-commit range' is stated but the test description for P1 doesn't clarify whether commits_for_range is tested on ranges with 2+ commits where only some add files. Test gap: commits_for_range on a 3-commit range where only the middle commit adds a file should attribute added_paths to that commit only, not the range.
  - _must_address_by_: `planner`
- **CRITICAL** `PLAN-RISK_SKEPTIC-001` (raised in `plan` / `plan_council_risk_skeptic`): Marker replacement is unspecified. Plan says 'ASCII-safe sentinel' but does not name it. Current marker is `"\x1eESCSHA\x1e"` (control chars on both sides). Replacement must be verified to not appear in git output (commit SHAs are hex-only, so any ASCII string works—but this assumption should be explicit, not implicit). Without seeing the concrete sentinel, we cannot verify the fix is complete.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-RISK_SKEPTIC-002` (raised in `plan` / `plan_council_risk_skeptic`): Five pending assumptions (PLAN-ASSUMP-001 through 005) are deferred without justification. PLAN-ASSUMP-001 (attribution to PR 10440 may be wrong) is CRITICAL to root-cause correctness; PLAN-ASSUMP-002 (PR was actually merged, not drafted) is CRITICAL for validity. If these assumptions are false, the regression test pins the wrong commit, and the fix misses the actual bug. Resolve or explicitly accept risk before landing.
  - _must_address_by_: `planner`
- **HIGH** `PLAN-RISK_SKEPTIC-003` (raised in `plan` / `plan_council_risk_skeptic`): Pre-drafted regression test (`tests/regressions/test_issue_10499.py`) is untracked in working tree and not shown for review. Plan says 'Adopt it; extend only if a case is missing'—this is speculative adoption. The test must be reviewed for correctness before committing: does it actually reproduce the `splitlines()` failure, or does it accidentally pass with both old and new markers?
  - _must_address_by_: `planner`
- **MEDIUM** `PLAN-RISK_SKEPTIC-004` (raised in `plan` / `plan_council_risk_skeptic`): Historical data corruption scope is unassessed.
