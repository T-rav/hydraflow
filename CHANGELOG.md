# Changelog

All notable changes to HydraFlow. Stable tags are cut by hand on a promoted `main` SHA;
`main` itself is the rolling integration tip and is **not** a release. The release policy,
what a tag promises, and the cut recipe live in
[`docs/wiki/patterns.md` → Release policy](docs/wiki/patterns.md#release-policy--stable-tags-vs-the-rolling-main-tip).

## Unreleased

- Ubiquitous language: the **adversarial planning ensemble** is renamed off "Council", so
  "Council" now names exactly one thing in this repo — the `agents/council/` governance
  layer (ADR-0053). `PlanCouncil`→`PlanEnsemble`, `DecompositionCouncil`→`DecompositionEnsemble`,
  `CouncilTally`→`EnsembleTally`, `src/plan_council{,_prompts}.py`→`src/plan_ensemble{,_prompts}.py`,
  `src/decomposition_council.py`→`src/decomposition_ensemble.py`, plan-flow node `council`→`ensemble`,
  stage strings `plan_council_*`→`plan_ensemble_*`, ledger source `decomposition_council`→
  `decomposition_ensemble`, prompt ids `decomposition_council_{direction,validation}`→
  `decomposition_ensemble_*`. `Ensemble` was chosen over `Panel` (owned by the UI) and `Jury`
  (same fiduciary-confusion class GNAA rejected "Board" for). Three pre-rename spellings keep
  being READ but are never written: the persisted stage string `plan_council_risk_skeptic`, the
  `hydraflow-council-review` transient label, and the MockWorld seed key `shape_council`
  (`tests/regressions/test_plan_ensemble_rename_compat.py`). ADR-0064/0105 keep their prose;
  only their source citations are repointed so the P2 drift gate keeps firing.
- Ubiquitous language: the multi-model ADR review ensemble is renamed off "Council" so the
  word names only the governance layer (ADR-0053 single-valued terms). `ADRCouncilReviewer` →
  `ADRReviewPanel`, `ADRCouncilResult`/`CouncilVote`/`CouncilVerdict` → `ADRReviewPanelResult`/
  `PanelVote`/`PanelVerdict`, and the term file `docs/wiki/terms/adr-council-reviewer.md` →
  `adr-review-panel.md` (same ULID, so inbound term edges hold). Two pre-rename keys are still
  **read**: the `## Council Amendment Notes` heading already written into ADRs on disk, and a
  `COUNCIL_RESULT:` transcript header from a stale prompt — dropping either fails silently
  (duplicated amendment block; verdict discarded as NO_CONSENSUS). `PlanCouncil`,
  `DecompositionCouncil` and the rest of the adversarial pipeline are untouched (#11764).
- Governance: the `agents/console/` layer is renamed **the Council, with chambers** per the
  2026-08-25 PAAA house standard (lineage: "console" → "Board" → Council, GNAA record
  `council/decisions/general/0009`). `agents/council/`, `make council-conformance`,
  `scripts/check_council_conformance.py`, the `council_ledger` CI filter, and
  `docs/methodology/councils-of-personas.md`. `make console-conformance` and
  `--agents-console` / `AGENTS_CONSOLE=1` remain as deprecated aliases; pre-rename
  `hydraflow-kernel.lock` files still read. Decision records keep their era's name and
  filenames — the rename is recorded as ARCH-0003, not applied to ARCH-0001 (#11741).
- Packaging: the wheel now ships the flat `src/` modules and `assets/`, so
  `uv pip install git+https://github.com/T-rav/hydraflow@<tag>` yields a working `hydraflow`
  console script (`--version` / `--help`); 21 `from src.<mod>` imports in 11 modules rewritten
  bare; `setuptools` added to the `test` extra (#11580, #11591). Running the server still
  needs a checkout — templates, prompts and the UI bundle are not in the wheel (#11589).

## v1.0.0 — 2026-08-21 — stable base

**What stable means.** v1.0.0 is the first pinned, known-good HydraFlow for downstream
HydraFlow-format repos (amplifier, harvestd, Signal Room, and every `make stamp` bootstrap)
to build on. The bar, per the *v1.0.0 — stable base* milestone: no open data-loss or
wrong-branch paths (the squash-merge worktree GC class #11502, the wrong-branch worktree
creation #11501, the closed-issue landed-check gap #11503/#11507, the false-close blind spot
#11481 are all closed); `main` CI green on the promoted SHA and the last
`RC Promotion Scenario` run green; zero open high-severity code-scanning alerts; no open P0; the version
bumped `0.9.7 → 1.0.0` and the `v1.0.0` tag placed on the **promoted `main` SHA** — never on
`staging` or on a checkout `HEAD`. Anything merged after that SHA is `main`, not v1.0.0.

**Scope.** 778 PRs merged to `staging` after the 0.9.7 bump (#9763, merged
2026-07-18 02:00 UTC) through 2026-08-21, carried to `main` by 56 RC promotions
(#9972 2026-07-19 → #11561 2026-08-21).
637 user-visible changes are listed below; the factory's own maintenance churn
(141 PRs) is collapsed into the summary lines at the end of this section. PRs the
factory titled `Fixes #N:` are bucketed by what they deliver — a feature-class issue closed by a
`Fixes #N:` PR is listed under Features, a regression pin under Tests.

**Headline changes.**

- Credit failover: Claude credit exhaustion reroutes work spawns to z.ai GLM instead of pausing the factory (ADR-0119, #10964).
- In-framework flow (DAG) primitive: every pipeline phase (triage, plan, implement, review) and the wiki compiler now run on one flow substrate; bespoke control code retired (#10684–#10703).
- Observability moved out of the factory: Honeycomb/OTel and Sentry removed, ownership handed to the SRE agent (ADR-0118, #10950, #10954).
- Test-suite parallelisation and CI tiers: `pytest -n auto` with serial scenarios, impacted-test selection, duration ratchet, sharded RC sandbox suite, `--forked` regression lane (#10113–#10126, #10308, #11011).
- Worktree and branch safety: squash-aware `WorkspaceGCLoop`, landed-check on closed issues, branch-identity-verified worktree creation, closing-keyword parsing folded onto one regex (closes #11502, #11503, #11507, #11501, #11481).
- Stillness / vitals instrumentation: setpoint register, finder calibration, judge calibration, vitals methodology, loop faceplates, sensing ladder (ADR-0120, ADR-0126, ADR-0127, ADR-0133).
- Operator console redesign and the supervisor operating contract (epics #10556, #10733).

### How the next tag is cut

Full recipe and rationale: [`docs/wiki/patterns.md` → Release policy](docs/wiki/patterns.md#release-policy--stable-tags-vs-the-rolling-main-tip). In short:

1. Milestone at 0 open, `main` CI green, last `RC Promotion Scenario` run green, `gh api 'repos/{owner}/{repo}/code-scanning/alerts?state=open&severity=high' --jq length` prints `0`, no open P0.
2. Open the version-bump PR (`pyproject.toml`, `src/__init__.py`, `src/ui/package.json` + lockfile, this file) against `staging`; merge it; let the next RC promote it to `main`.
3. `git fetch origin main && git tag -a vX.Y.Z <promoted main sha> -m "vX.Y.Z — <name>" && git push origin vX.Y.Z && gh release create vX.Y.Z --title "vX.Y.Z — <name>" --notes-file <this section>`.
4. Nothing cuts the tag for you: the ADR-0011 epic-close release trigger has not existed since #2689 (#11569). Tag the promoted `main` SHA by hand — never `staging`, never a checkout `HEAD`.
